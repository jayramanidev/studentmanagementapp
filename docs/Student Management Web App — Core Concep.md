Student Management Web App — Core Concept & RoadmapFor tuition institutes preparing students for competitive & police exams (Constable, PSI, STO, GPSC, UPSC, and similar)1. Core IdeaA centralized operations hub that replaces manual registers, scattered WhatsApp groups, and paper mark-sheets with one operational dashboard. The web app does not host or run digital tests; all mock tests and exams are conducted offline on paper/OMR at the institute.The platform serves as the single source of truth to record, analyze, and publish offline exam performance, track attendance, and keep students and parents aligned on exam-readiness.Primary goal: Eliminate administrative friction in logging classroom test marks and daily attendance while giving students and parents instant, transparent visibility into academic performance trends.2. User Roles & PermissionsRoleCore ResponsibilitiesKey PermissionsAdmin / Institute OwnerInstitute setup, branch management, staff oversight, overall analyticsFull CRUD across the instituteExam CoordinatorSchedules physical tests, oversees batch score entries, generates cross-batch rank listsCreate offline test events, publish marks, generate performance reportsTeacherMarks daily attendance, inputs test marks, uploads study material/answer keysEnter attendance & marks for assigned classes, upload notes, message parentsStudentTracks attendance, reviews offline test marks, analyzes personal progress, downloads notesRead-only access to own marks, ranks, attendance, and study materialsParent / GuardianMonitors student's test scores, tracks weak areas, checks attendanceRead-only access to linked child's marks, attendance, and institute noticesKey Success MetricsMarks publication turnaround (hours between offline test completion and mark entry)Parent portal engagement (percentage of parents reviewing published test marks within 48 hours)Attendance logging compliance (marked within 24 hours of class)Performance progression tracking (cohort-level score improvement across consecutive mock tests)3. Feature PrioritizationPhase 1 — MVP: Core Tracking & Offline Mark ManagementAuth & RBAC: Scoped access for Admin, Coordinator, Teacher, Student, and Parent.Academic Structure: Institute → Center/Branch → Class/Batch → Subject.Offline Test & Mark Entry:Create test entries (Subject, Test Type, Max Marks, Date, Answer Key PDF).Fast bulk mark entry interface (spreadsheet-like grid) and CSV score import.Automatic calculation of percentages, batch average, and class ranks.Student & Parent Performance View:Subject-wise score breakdown, test history, and visual trend charts.Class rank and highest/average score benchmarks for each test.Attendance System: Period/daily attendance marking with low-attendance flags.Notice Board & Study Material: Class-scoped announcements and PDF material sharing.Alerts: Basic email and in-app alerts when new test marks are published.Phase 2 — Performance Analytics & CommunicationDeep Analytics:Student exam-readiness index (identifying consistently weak subjects).Batch vs. batch performance comparisons.Automated Scorecards: One-click PDF report card generation for parent-teacher meetings.Direct Alerts: SMS / WhatsApp notification gateway integration for instant test score delivery to parents.OMR / Mark-Sheet Upload: Bulk score ingestion via formatted scanner/Excel export sheets.Security & Audit: Two-factor authentication (2FA) for staff and audit logging for mark modifications.Phase 3 — Scale & Advanced InsightsAI Performance Diagnostics: Automated strengths/weaknesses summary per student based on historical test scores.Multi-Branch Operations: Centralized oversight for multi-center coaching networks.Multi-Language UI: Gujarati, Hindi, and English localization.Fee & Enrollment Tracking: Simple tuition fee ledger tied to student profiles.4. Key User Flows1. Offline Test Creation & Score Entry (Teacher / Coordinator)Teacher creates a test entry in the portal: selects Class, Subject, Test Date, and Maximum Marks.Students take the physical paper/OMR test at the institute.Teacher grades physical papers and opens the Bulk Mark Entry grid on the web app.Teacher enters marks obtained and qualitative remarks per student (or uploads a CSV).Teacher clicks Publish Marks, which calculates batch ranks and triggers notifications.2. Student Performance Review (Student)Student logs in and navigates to the Test Performance tab.Views latest test score alongside the class topper's score, batch average, and their rank.Downloads the official test answer key/solution sheet uploaded by the teacher.Reviews historical line charts to track score trajectory across previous weeks.3. Parent Monitoring (Parent)Parent receives an SMS/notification: "Jay's PSI Mock Test #4 marks are published: 82/100 (Rank 4/45)".Parent logs in to the dashboard to view the full score history, teacher feedback, and attendance percentage.Parent can send an in-app inquiry to the teacher regarding weak subjects if needed.5. High-Level Data ModelInstitute: id, name, address, contact_phone, created_atCenter / Branch: id, institute_id (FK), name, cityUser: id, name, email, phone, password_hash, role (admin | coordinator | teacher | student | parent), statusStudentProfile: user_id (FK), class_id (FK), roll_no, target_exam (e.g., PSI, Constable, GPSC), dobParentStudentLink: parent_user_id (FK), student_user_id (FK), relationshipClass / Batch: id, center_id (FK), name, target_exam, start_time, end_timeSubject: id, class_id (FK), name, assigned_teacher_id (FK)Attendance: id, student_id (FK), class_id (FK), date, status (present | absent | late), marked_by (FK)OfflineTest: id, class_id (FK), subject_id (FK), title, test_type (weekly_unit | full_mock | surprise_quiz), total_marks, passing_marks, test_date, solution_file_url, created_by (FK), is_published (bool)TestMark: id, test_id (FK), student_id (FK), marks_obtained (decimal), is_absent (bool), rank_in_class, teacher_remarks, entered_by (FK), updated_atStudyMaterial: id, class_id (FK), subject_id (FK), title, file_url, uploaded_by (FK), uploaded_atNotice: id, institute_id (FK), target_class_id (FK, nullable), title, content, published_at6.
